# AI 语音外呼营销系统 —— 需求说明书（纯需求视角）

## 产品总目标

系统要能**代替人工客服自动外呼客户**，通过实时语音与客户自然对话，完成客情回访与营销推广，自动判定每个客户的意向结果，沉淀完整通话数据，支持批量作业和结果导出复盘。整个系统要做到：**话术可控、可规模化外呼、结果可复盘、营销场景可快速切换**。

---

## 一、话术可控：高频/敏感场景用固定话术，开放问题交给大模型

### 需求 1.1：两层应答机制

- 每听到客户说一句话并转成文字后，系统必须**先查固定话术库，再考虑调用大模型**：
  - 命中固定话术 → 直接播报对应话术，**不调用大模型**（要求零延迟、回答内容 100% 可控）
  - 未命中 → 才交给大模型结合业务背景和上下文生成回复
- 这个"先拦截、后兜底"的顺序是硬性要求，拦截点在大模型生成之前。

### 需求 1.2：固定话术库的结构

每条固定话术必须包含 5 个要素：

1. **触发词列表**：一组关键词，用"包含式模糊匹配"（例如"别…打…电话"中间可隔字）
2. **固定回答文本**：20-40 字
3. **是否结束通话**：命中后是否立即收尾挂断
4. **营销定性**：命中即确定结果——感兴趣 / 不感兴趣 / 中立
5. **优先级**（0-10）：多条可能命中时，优先级高的生效

### 需求 1.3：内置话术的覆盖范围（冷启动要求）

系统启动即自带一份基础话术库，且**刻意保持精简**，只覆盖"意图明确、无需个性化"的场景：

- **身份否认类**（最高优先级）：客户说"打错了 / 不是本人 / 找错人"→ 礼貌道歉并立即结束，定性为"不感兴趣"
- **投诉免打扰类**（最高优先级）：客户说"别再打电话 / 骚扰 / 拉黑 / 投诉"→ 道歉并承诺加入免打扰名单，立即结束
- **听不清类**（普通优先级）：客户说"听不清 / 没听见"→ 道歉并表示重新说一遍，**不结束通话**，定性"中立"

**明确禁止**：不得为"你是谁、多少钱、怎么买、太贵、考虑考虑、嗯/好的"等需要上下文或个性化的场景设置固定话术——这些必须交给大模型；固定话术文本中**不允许出现具体产品名、价格、优惠金额**等硬编码信息。

### 需求 1.4：大模型兜底回复的行为规范

大模型回复时必须遵守：

- 人设：该业务的专业客服，正在进行电话外呼，并已知晓自己刚说过的开场白
- 注入完整业务背景作为知识来源
- 每次回复控制在 1-2 句话，口语化、纯文本，不带格式符号和表情
- 语气护栏：平稳亲切像真人，**禁止"太好了/太棒了/哇"等激动夸张的表达**
- 结束策略：
  - 只有客户明确表达购买意向（怎么买、我要、下单、要专员联系）才算"感兴趣"并可结束
  - 只有客户明确强烈拒绝（不需要、不感兴趣、没时间）才算"不感兴趣"并可结束
  - 客户询问价格、产品信息、效果等属于"中立"，**必须继续对话，不得提前挂断**
  - 原则是"宁可多聊几轮，也不要过早结束"
  - 不得编造电话号码等不确定信息

### 需求 1.5：固定话术命中后的联动

命中固定话术不只是播报，还必须：

- 若该话术带明确营销定性且本通电话尚未上报结果 → 立即上报结果，并把这句固定话术补录进对话记录
- 若该话术标记"结束通话" → 立即停止收音和生成，但**必须让这句告别话术完整播完再挂断**（等待时长按话术字数估算）

### 需求 1.6：通话结束的三种情形（都要保证告别语播完）

1. **自然告别**：系统持续监听自己说的每句话，一旦出现"再见/再会/拜拜"等告别词 → 停止收音 → 对完整对话做最终结果裁决 → 上报 → 等告别语播完 → 挂断
2. **客户沉默**：客户连续 60 秒不说话（每轮任何一方发言后重新计时）→ 主动说固定告别语"您好像有些忙，那就不打扰您了…"→ 结果记"不感兴趣"，原因记"用户沉默超过60秒"
3. **轮次上限**：AI 已回复满 50 轮仍未告别 → 强制说告别语结束

## 二、可规模化：批量客户清单 + 逐客个性化话术 + 实时状态同步

### 需求 2.1：客户清单导入

- 运营可上传一份客户清单表格（每行一个客户，列名不固定，如姓名、性别、购买产品、购买时间等）
- 系统要求：
  - 每次上传视为一个**批次**，生成唯一批次号，记录上传时间、总人数、已完成人数、原始列名
  - 每个客户保存：所属批次、原始行号、**整行原始数据**、以及一组结果字段（初始为"待呼叫"）
  - 上传完成后返回：批次号、总人数、列名清单、前 3 条预览，供前端确认
  - 支持恢复查看最近一次批次，支持重新拉取某批次全部客户

### 需求 2.2：客户资料可在线编辑

- 前端允许运营逐个修改某客户的原始资料字段，修改后立即保存并同步刷新页面

### 需求 2.3：逐客个性化话术（呼出前即时生成）

每次对某个客户发起呼叫前，系统必须为**这一通电话**单独生成：

1. **个性化业务背景**（由大模型生成）：
   - 输入：该客户的整行资料
   - 要求：自然融入客户姓名、购买产品、购买时间；说明本次回访目的（关心体验/推新品/送优惠）；100-200 字；口语化、无格式符号
   - 如果资料里有购买日期（需兼容多种字段名和日期写法），先算出"距今多少天/月"一并给到大模型，让话术能自然说出"您 X 个月前购买了…"
   - 生成失败时回退到一段通用背景，不能阻塞呼叫
2. **个性化开场白**（按规则生成，不走大模型）：
   - 从资料中按多个候选字段名找出姓名和性别
   - 拼成"您好，请问是{姓名}{女士/先生}吗？"；找不到姓名时用"您好，请问是本机主人吗？"
   - **开场白必须直接语音播报，不经过大模型**，保证首句响应最快
3. 这份个性化业务背景和开场白要随本次通话会话下发给执行对话的一端，用于构建本通电话的人设和知识背景

### 需求 2.4：批量外呼的调度规则

批量模式按客户顺序**逐位串行**呼叫：

1. 从第一位开始，界面上高亮当前正在呼叫的客户，显示进度"第 N 位 / 共 M 位"
2. 为当前客户发起呼叫（此时触发 2.3 的个性化生成，状态置为"进行中"并实时通知界面）
3. 等待该通电话结束，判定结束有两个依据：
   - 收到该客户"已完成"的状态通知
   - 或**活动超时**：连续 60 秒没有任何新的对话动静即视为异常超时（期间每出现一句新对话就重置这个计时）
4. 单个客户呼叫失败**不中断整个批次**，记录错误后继续下一位
5. 每通结束后**倒计时 10 秒**再呼叫下一位（最后一位除外）
6. 运营可随时停止批量任务

### 需求 2.5：实时状态推送

- 任何客户的状态变化（开始呼叫、结果落定）必须**即时推送给所有打开的页面**，界面表格对应行立刻刷新（状态、时长、结果、原因、对话记录）
- 批量调度器也依赖这个推送来判断"当前这通是否已结束"
- 推送通道异常的连接要自动清理，不影响其他页面

## 三、可运营复盘：结果自动分类 + 全程对话记录 + 结果导出

### 需求 3.1：全程对话记录

- 通话过程中，双方每说一句话都要即时记入本通的对话流水（区分"客户说"和"客服说"），并实时显示在运营界面上
- 通话结束时形成完整记录：本次通话的唯一标识 + 按时间顺序的完整对话文本

### 需求 3.2：营销结果的自动分类

每通电话必须归入以下结果之一，并附带一句判定原因：

- **感兴趣**：客户表达购买意愿、想了解更多、询问购买方式、同意接受后续联系
- **不感兴趣**：客户明确拒绝、不需要、要求别再打、身份不符、始终沉默忙碌
- 判定来源有三种，且一通电话**只允许上报一次结果**：
  1. **固定话术直接定性**：命中带定性的固定话术时立即确定，原因记"固定话术匹配：{触发的关键词}"
  2. **大模型终裁**（主要方式）：通话进入告别环节时，把完整对话流水交给一个轻量快速的大模型，只让它输出二选一的结果和一句话依据；这个裁决与播放告别语**同时进行**，不得拖慢挂断；裁决失败时兜底记"不感兴趣"
  3. **异常兜底**：沉默超时、超过轮次上限，直接记"不感兴趣"并注明具体原因
- 上报内容必须完整：通话状态、通话时长（秒）、营销结果、判定原因、完整对话记录；若告别语/固定话术还没来得及写入流水，要**补录进去**，保证导出记录不缺最后一句

### 需求 3.3：结果落库与批次进度

- 结果上报后立即持久化到该客户记录上，记录完成时间
- 所在批次的"已完成人数"加一

### 需求 3.4：结果导出

- 支持按批次一键导出结果表格，每行一个客户，内容为：
  - **原始清单的全部列**（保持上传时的字段）
  - 追加 6 列：通话状态（待呼叫/进行中/已完成/失败）、通话时长、营销结果（感兴趣/不感兴趣/中立）、原因备注、对话记录（格式化为"客服：…/客户：…"逐行文本）、通话时间
- 导出文件可下载，文件名带批次号

## 四、可快速换行业场景：业务背景配置化 + 话术自动生成

### 需求 4.1：场景即配置

- 系统维护三个运行时可改的全局配置：**业务背景描述**（一段长文，说明这次营销是做什么的）、**业务名称**（如某品牌名）、**默认开场白**
- 修改这三项**不需要重启服务、不需要改任何代码**，下一通电话立即生效

### 需求 4.2：切换场景时自动生成配套话术

运营提交新的业务背景后，系统自动执行：

1. 更新全局配置，清空旧的追问话术
2. 把业务背景和业务名称交给大模型，自动生成一套新的固定话术，生成要求：
   - 只提供几个同场景的示例作为参照（身份确认/明确拒绝/询问价格各一条）
   - 只允许产出约 4 条：**明确拒绝类 3 条**（打错了 / 不需要 / 别骚扰）+ **听不清类 1 条**
   - 每条含：类别、触发关键词列表、回答文本、是否结束、营销定性、优先级、描述
   - 约束：回答 20-40 字；结束类必须含"再见"；关键词要简短；不得出现具体产品/价格/优惠；不得为语气词和个性化场景设计话术
3. 用新话术**全量替换**旧话术库，并存档一份（按业务名命名），便于复用
4. 生成或解析失败时，回退到一套内置默认话术，保证系统可用
5. 前端能查询"话术是否已就绪"，就绪前提示等待

### 需求 4.3：场景贯穿到每通电话

- 每次发起呼叫，都把**当前生效的业务背景**随会话带给对话执行端，用于构建人设
- 若是逐客批量模式，则用**该客户的个性化背景覆盖全局背景**
- 即：换场景 = 改一段配置文字，话术库自动重建，人设自动重组

## 五、端到端完整流程（一通批量外呼的生命周期）

1. 运营通过企业统一账号登录系统
2. 配置/切换营销场景 → 系统自动生成配套固定话术并热替换
3. 上传客户清单表格 → 建立批次，所有客户初始状态"待呼叫"，可在线编辑个别客户资料
4. 启动批量外呼 → 系统按顺序取第 N 位客户
5. 为该客户即时生成个性化业务背景 + 个性化开场白 → 状态置"进行中"并实时通知所有页面
6. 建立语音通话 → **开场白直接语音播报**（不等大模型）
7. 进入对话循环：听客户说话 → 先查固定话术（命中直接回答，可顺势结束）→ 未命中交大模型应答；每句话实时记入流水并显示在界面；全程受"沉默 60 秒"和"最多 50 轮"守护
8. 触发结束（出现告别词 / 固定话术要求结束 / 沉默超时 / 超轮次）→ 停止收音 → 大模型对全程对话做最终意向裁决 → 结果连同完整对话记录落库 → 实时推送"已完成"
9. 批量调度器确认本通结束（或 60 秒无动静判超时）→ 倒计时 10 秒 → 呼叫下一位；中途失败跳过继续
10. 全部完成后，运营一键导出结果表格：原始客户信息 + 状态、时长、意向结果、原因、完整对话记录、通话时间，用于转化复盘

## 六、关键参数汇总（复刻时必须保留的阈值）

| 参数 | 值 |
|---|---|
| 客户沉默超时 | 60 秒 |
| AI 最大回复轮次 | 50 轮 |
| 批量呼叫间隔 | 倒计时 10 秒 |
| 通话活动超时（批量调度用） | 60 秒无新对话 |
| 固定话术回答长度 | 20-40 字 |
| 个性化业务背景长度 | 100-200 字 |
| 话术优先级范围 | 0-10，大者优先 |
| 营销结果枚举 | 感兴趣 / 不感兴趣 / 中立 |
| 通话状态枚举 | 待呼叫 / 进行中 / 已完成 / 失败 |
| 告别识别关键词 | 再见 / 再会 / 拜拜 |
| 结果上报 | 每通仅一次，须含完整对话记录 |

> 本说明书只描述"系统必须做到什么"，不涉及任何具体技术实现；交给 coding agent 时，让它根据目标框架自行选择实现手段即可。
