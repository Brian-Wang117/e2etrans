# AI 语音外呼营销系统 · 子系统 1：单通对话引擎 设计文档

- **日期**：2026-08-19
- **需求来源**：`docs/superpowers/plans/voice_outbound_bot_requirements.md`（需求一、三 3.1/3.2，以及 1.1–1.6、3.1、3.2 相关条款）
- **状态**：已评审通过（用户确认）

## 0. 范围与前提

整个外呼营销平台拆分为 4 个子项目，按依赖顺序实施：**1 单通对话引擎（本文档）→ 2 客户与批次管理 → 3 场景配置化 → 4 运营前端与导出**。

关键前提决策（均已与用户确认）：

| 决策点 | 结论 |
|---|---|
| 外呼形态 | 方案 A：沿用浏览器 JsSIP 电话桥。SIP 注册/拨打仍在浏览器（复用 ocssaas 线路），服务端负责话术拦截、守护、终裁、上报与（后续）批次调度 |
| 拦截架构 | 先 A 后 B 演进：复用豆包 ASR 终稿做话术匹配，命中则 interrupt + say_hello 注入；匹配器做成可替换接口，未来可切"前置独立 ASR + 音频闸门" |
| 兜底回复 | 继续用豆包端到端会话自然应答，人设/业务背景/语气护栏经 system_role 注入，不另接文本 LLM |
| 终裁模型 | Qwen（qwen-flash），复用现有 DashScope 配置与客户端（与字幕翻译同一凭证） |
| 验证入口 | 复用现有电话/网页面板，本子系统只做服务端引擎 + 最小结果展示；正式运营界面属子系统 4 |
| 阈值 | 按需求文档执行（沉默 60s、50 轮、告别词 再见/再会/拜拜 等），实测后再调 |

**不在本子项目范围**：客户清单/批次/调度器（子系统 2）、场景配置热更新与话术自动生成（子系统 3）、运营工作台与结果导出（子系统 4）。

## 1. 总体架构

在 `app/realtime/` 旁新增 `app/outbound/` 包，`RealtimeGateway` 在关键事件点挂接 CallDirector，不重写现有链路：

```
浏览器(JsSIP) ⇄ 网关 RealtimeGateway ⇄ 豆包端到端会话
                      │ ASR终稿/助手文本/音频事件
                      ▼
              CallDirector（单通状态机）
              ├─ ScriptMatcher（话术拦截，可替换接口）
              ├─ EndGuards（告别词监听 / 60s沉默 / 50轮上限）
              ├─ Adjudicator（Qwen 终裁）
              └─ ResultReporter（每通一次性上报，落库）
```

| 模块 | 职责 | 依赖 |
|---|---|---|
| `app/outbound/script_library.py` | 话术数据模型、匹配算法、优先级裁决、内置冷启动话术、加载校验 | 无 |
| `app/outbound/call_director.py` | 单通生命周期状态机：拦截决策、结束守护、触发终裁与上报 | ScriptMatcher、EndGuards |
| `app/outbound/adjudicator.py` | 轻量终裁：完整流水 → qwen-flash → `{"result","reason"}`；超时/失败兜底 | DashScope 客户端 |
| `app/outbound/persona.py` | 人设基座+语气护栏+结束策略+业务背景拼 system_role；默认开场白 | 无 |
| `app/realtime/gateway.py`（改造） | ASR 终稿先过 director；助手文本事件喂告别词监听；会话结束钩子 | CallDirector |

**拦截时序（方案 A）**：豆包 ASR 终稿（451 非 interim / 459）到达网关 → director 匹配话术 → 命中：立即 `interrupt()` 掐掉豆包可能已启动的回复，再 `say_hello(话术文本)` 直接 TTS 播报（绕过大模型，内容 100% 可控）；未命中：不干预，豆包按注入人设自然应答。命中延迟≈ASR 完成时刻。

## 2. 固定话术库

### 2.1 数据模型

```python
@dataclass(frozen=True)
class Script:
    id: int | None              # DB 主键
    category: str               # 类别：身份否认 / 投诉免打扰 / 听不清 / 明确拒绝…
    triggers: tuple[str, ...]   # 触发词列表
    reply: str                  # 固定回答，20-40 字
    end_call: bool              # 命中后是否立即收尾挂断
    verdict: str                # 营销定性：感兴趣 / 不感兴趣 / 中立 / ""（不定性）
    priority: int               # 0-10，大者优先
    description: str            # 描述（存档/管理用）
```

### 2.2 匹配算法

- **包含式有序子序列匹配**：触发词按字符顺序出现即命中，中间可隔任意字（双指针子序列判定）；顺序颠倒不命中；
- 对 ASR 终稿逐一判定所有话术的所有触发词，命中候选集取 `priority` 最高者；同优先级取触发词更长（更具体）者；仍并列取库内顺序；
- 仅对 ASR 终稿匹配，不对 partial 中间结果拦截；
- 空文本、纯语气词不匹配；
- `ScriptMatcher` 仅暴露 `match(text) -> Script | None`，话术来源（内存/DB/生成）注入——未来切方案 B 的替换点。

### 2.3 内置冷启动话术（3 条，刻意精简）

| 类别 | 触发词 | 固定回答 | 结束 | 定性 | 优先级 |
|---|---|---|---|---|---|
| 身份否认 | 打错了、不是本人、找错人 | 非常抱歉打扰到您了，可能是我们这边登记有误，祝您生活愉快，再见。 | 是 | 不感兴趣 | 10 |
| 投诉免打扰 | 别再打、骚扰、拉黑、投诉 | 很抱歉给您带来困扰，我会把您加入免打扰名单，不再来电，再见。 | 是 | 不感兴趣 | 10 |
| 听不清 | 听不清、没听见 | 不好意思，那我放慢一点，再给您说一遍。 | 否 | 中立 | 5 |

需求 1.3 的禁止项（"你是谁/多少钱/太贵/考虑考虑"等不设固定话术、不硬编码产品/价格）通过下述校验与评审保证。

### 2.4 硬性校验

加载与生成话术时统一执行，违反条目丢弃并告警：

- 回答 20-40 字；
- `end_call=true` 的回答必须含"再见"；
- 触发词与回答不得出现价格数字、产品名硬编码（禁用词/模式扫描）；
- 优先级必须在 0-10；定性必须在枚举内或为空。

### 2.5 存储

SQLite 新增 `scripts` 表（2.1 字段 + `library_name`、`created_at`）；内置话术首次启动自动灌入。子系统 3 的话术生成/存档复用此表。DB 加载失败时回退内存内置话术。

## 3. 单通生命周期

状态机：`开场播报 → 对话中 → 收尾中（告别） → 已结束`；旁路终态：`话术结束`、`异常结束`。

### 3.1 开场

会话建立时 `say_hello(开场白)`。子系统 1 使用全局默认开场白（配置默认值，如"您好，请问是机主本人吗？"）；`session.start` 协议预留 `opening_text`、`business_background` 可选字段（子系统 2/3 使用）。

### 3.2 对话循环

每句客户话（ASR 终稿）→ director 匹配：

- **未命中**：不干预，豆包自然应答；
- **命中**：`interrupt()` + `say_hello(话术)`；话术补录为 agent 话轮（`source=script`）；带定性且本通未上报 → 立即上报（原因 `"固定话术匹配：{命中触发词}"`）；`end_call=true` → 停止收音，按字数估算播报时长（约 0.25 秒/字 + 1.5s 缓冲）等待播完后挂断。

### 3.3 结束守护（先到先触发）

| 守护 | 触发 | 动作 |
|---|---|---|
| 告别词监听 | 助手最终文本（assistant.text.done）含 再见/再会/拜拜 | 停止收音 → 并行启动终裁 → 等告别语 TTS 播完（`assistant.audio.done` + 0.5s 余量）→ 挂断 |
| 客户沉默 60s | 任何一方发言后重新计时，60s 无新话轮 | `say_hello("您好像有些忙，那就不打扰您了，祝您生活愉快，再见。")`；结果直接记"不感兴趣"、原因"用户沉默超过60秒"（不走终裁）；播完挂断 |
| 轮次上限 | 助手回复满 50 轮 | 强制告别语收尾，之后照常走终裁 |

**停止收音实现**：网关置 `muted_input` 标志丢弃后续 `input_audio.append`（电话模式为常开流，不能关麦克风），并对豆包 `end_asr()`。

### 3.4 终裁（与告别播报并行）

- 输入：完整对话流水（"客服：…/客户：…"格式）；
- 模型：qwen-flash，提示词只要求输出 JSON `{"result":"感兴趣|不感兴趣","reason":"一句话"}`，超时 5 秒；
- 与告别播报并行，不阻塞挂断；挂断时终裁未回则最多再等 3 秒后落库；
- 失败/超时/解析失败兜底："不感兴趣、原因：终裁失败"。

### 3.5 结果上报（每通仅一次）

- `ResultReporter` 标志位 + 锁保证幂等；
- 上报内容：通话状态、时长（秒，建连→挂断）、营销结果、判定原因、完整对话记录（告别语/固定话术未入库先补录）；
- 落 `call_results` 表（session_id 唯一键）；批次进度联动由子系统 2 订阅上报事件。

## 4. 人设与豆包会话参数

- **system_role 拼装**（`persona.py`）：人设基座（专业外呼客服、正在进行电话外呼、已知自己刚说的开场白）+ 语气护栏（平稳亲切，禁止"太好了/太棒了/哇"等夸张表达，1-2 句口语化纯文本）+ 结束策略（仅明确购买意向/明确强烈拒绝才可收尾；询问价格/产品/效果属中立必须继续聊；宁可多聊不过早结束；不编造电话号码）+ 业务背景（子系统 1 用配置默认值，`session.start.business_background` 可覆盖）；
- **bot_name** 改配置项，≤20 字符（超长自动截断，已知服务端约束）；
- **不覆盖现有翻译场景**：新增场景 `outbound_default`（中文外呼人设），前端场景下拉多一个"外呼营销"选项；现有模拟器场景不变；
- **输入模式**：外呼场景强制 `input_mode=audio`（服务端 VAD 常开流），与电话模式一致。

## 5. 存储与协议变更

**存储**（SQLite，复用 Repository，同步调用走 `asyncio.to_thread` 包装）：

- `scripts` 表：见 2.5；
- `call_results` 表：session_id 唯一键、status（本通结束时为 已完成 或 失败，枚举与需求六对齐；待呼叫/进行中 属子系统 2 批次字段）、duration_seconds、result、reason、reported_at；
- `turns` 表：增加 `source` 标记字段（`asr`/`text`/`script`/`farewell`），话术与告别语补录为 agent 话轮。

**协议**（向后兼容，缺省走默认）：

- `session.start` 新增可选：`opening_text`、`business_background`；
- 服务端新增事件：`script.hit`（命中提示）、`result.reported`（结果+原因）。

**前端最小改动**（验证用）：场景下拉加"外呼营销"；结果横幅展示 `result.reported`。

## 6. 错误处理

| 故障 | 处理 |
|---|---|
| 话术 DB 加载失败 | 回退内存内置话术，记告警 |
| `say_hello` 注入失败 | 降级 `send_text_query` 让豆包兜底，保证对话不断 |
| 终裁失败/超时/JSON 损坏 | 兜底"不感兴趣、原因：终裁失败" |
| 结果上报失败 | 重试一次后记日志，不阻塞挂断 |
| 豆包会话中途断开 | 走现有网关错误路径；director 标记"异常结束"，已产生的流水照常落库 |

## 7. 测试计划

pytest，沿用现有 `tests/` 风格：

1. `test_script_library.py`：有序子序列匹配（隔字命中/顺序颠倒不中）、优先级与长度裁决、内置话术与硬性校验（20-40 字、结束含再见、禁硬编码、优先级范围）；
2. `test_call_director.py`：命中拦截（interrupt+注入）、沉默 60s、50 轮上限、告别词触发收尾、结果上报幂等；
3. `test_adjudicator.py`：mock DashScope——正常、超时、JSON 损坏三路径；
4. `test_gateway.py` 扩展：fake 豆包客户端跑完整通话两条主链路——命中结束类话术挂断、自然告别+终裁落库。

## 8. 已知风险与后续

- **say_hello 中途可用性**：现有代码仅在会话开始使用过；需实测对话中途 `interrupt()` + `say_hello()` 是否被豆包正常接受，若不可用则降级路径为 `send_text_query` 加指令前缀（接受 LLM 转述损耗）；
- 阈值（0.25s/字播报估算、缓冲时长、终裁等待窗口）实测后可调；
- 方案 B（前置 ASR 闸门）视真机拦截延迟体验再评估，接口已预留。
